> 纪律：**风险显式暴露 + 给规避方案 + 标注触发条件**；不确定的一律标风险，绝不默认「应该没问题」。

| R21 | **MEDIUM** | **插件侧错误从另外两条出口逃逸**（历史缺陷，评审五轮 🔴 必修-1/2/3；本行是「四条出口」的第 ③④ 条 + 边界）：<br>③ 插件调 `process.exit()` —— **不抛异常**，顶层 `catch` 与 `uncaughtException` 都接不到；<br>④ `run()` 被插件**拖住**（挂住事件循环 / `apply()` 返回永不 resolve 的 Promise）—— 既无异常也无退出，而旧看门狗只在**记录过异步异常**时才安装、且紧跟 `unref()` ⇒ 本形态下**根本没装 / 装了也永不触发** | 插件把宿主进程当成自己的 CLI 进程（启动自检后 `process.exit(0)`）；插件等一个永不到来的握手 / 死锁 / 忘了 resolve；插件 `kill -9` 自己 | 探针在写出 `__DSH_PROBE__` 前消失 ⇒ 装配器**无条件** `pushHostFatal()` ⇒ 插件 bug 判 `UPSTREAM_DRIFT`/AMBER + `checks` 归零。<br>**更危险的是「修一半」**：只加 `exit` 钩子而**不带完成位**时，`apply()` 里 `process.exit(0)` → 剩余检查是 `skip` 不是 `fail` → `errors.length === 0` → **GREEN / PASS / checks=6（假绿，比 AMBER 更危险：AMBER 至少不放行）** | ① **完成位** `runCompleted` 只在 `run()` 正常返回后置真，`emit()` 的 `ok = runCompleted && errors.length === 0`（未跑完**绝不**判 PASS）；<br>② `process.on('exit')` 钩子 + 自杀式信号处理器 → `plugin.early_exit`，`writeSync` 补输出报告、`process.exitCode = 1`；<br>③ 看门狗**无条件安装**、**不得 `unref`**（收尾显式 `clearTimeout`）→ `plugin.run_incomplete`；<br>④ 归属路由唯一事实源 `contract.mjs` 的 `probeProcessFailureRoute()`（插件侧一律落 check，**绝不**写 `hostFatal[]`） | 离线 [9.9]（路由 + 写入端不变量 + 崩溃路径不抛 + 完成位 + 装配器层 + 信标 + 源码守卫，含「不得 unref」回退即红）；离线 `test_offline.sh` [16] 四条出口（假宿主 + 真实探针 + 装配器真实实现）；真宿主 [8c]（exit / hang / SIGKILL × 10 条 + 假绿反证 2 条）；闸门 `tests/gate_plugin_side.sh`（7 份夹具 + 健康插件 17/17 防过度修正） |

**边界（不可捕获终止，🔴 必修-2「二选一」的方案②）**：`SIGKILL` / OOM / 原生 `abort` **不可捕获**——
探针来不及写结构化结果。此时装配器按**相位信标** `__DSH_PROBE_PHASE__` 归因：
**有信标**（终止发生在插件代码运行期间）→ 插件侧 check `plugin.abnormal_termination`，`hostFatal[]` 保持为空；
**无信标**（终止在宿主装配段）→ `hostFatal[]` → `UPSTREAM_DRIFT`（真上游信号不丢）。
> 为什么不能只「声明边界」了事：声明只解决「静默」，不解决「甩锅」——插件把自己 `kill -9`
> 也会被判成「上游变了，不是你的问题」。信标把「终止发生在哪一段」变成**证据**。
